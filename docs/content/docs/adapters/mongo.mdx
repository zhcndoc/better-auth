MongoDB 是一种流行的 NoSQL 数据库，广泛用于构建可扩展且灵活的应用程序。它提供了灵活的模式，便于数据建模和查询。

在开始之前，请确保您已安装并配置好 MongoDB。更多信息，请参见 [MongoDB 文档](https://www.mongodb.com/docs/)

## 安装

要使用 MongoDB 适配器，您需要安装 `@better-auth/mongo-adapter` 包：

```package-install
@better-auth/mongo-adapter
```

## 示例用法

### 副本集或分片集群

传入 `client`，适配器便会默认使用事务。副本集或分片集群请使用相应的连接字符串：

```ts title="auth.ts"
import { betterAuth } from "better-auth";
import { MongoClient } from "mongodb";
import { mongodbAdapter } from "@better-auth/mongo-adapter";

const client = new MongoClient("mongodb://localhost:27017/database");
const db = client.db();

export const auth = betterAuth({
  database: mongodbAdapter(db, {
    client,
  }),
});
```

发生并发写入同一文档时，MongoDB 会因写冲突中止其中一个事务，并要求应用重试。适配器最多重试此类事务 120 秒，因此在竞争激烈时，请求可能耗时更长，而不是直接失败。要缩短此上限，可在 `MongoClient` 上设置 `timeoutMS`；该选项也会影响此客户端上的所有其他操作。

重试会重新执行整个操作，包括 `before` [数据库钩子](/docs/concepts/database#database-hooks)以及接收事务的插件回调。应在 `after` 钩子中发送邮件和调用其他服务；该钩子只会在提交后运行一次。

### 独立服务器

独立 MongoDB 服务器不支持事务。使用 `MongoClient` 创建 `db`，并在不传入 `client` 选项的情况下将其传给适配器：

```ts title="auth.ts"
import { betterAuth } from "better-auth";
import { MongoClient } from "mongodb";
import { mongodbAdapter } from "@better-auth/mongo-adapter";

const client = new MongoClient("mongodb://localhost:27017/database");
const db = client.db();

export const auth = betterAuth({
  database: mongodbAdapter(db),
});
```

不使用事务时，如果后续写入失败，先前的写入可能仍会保留。迁移到副本集或分片集群后，传入 `client` 即可启用事务。请参阅 [MongoDB 的事务要求](https://www.mongodb.com/docs/manual/core/transactions-production-consideration/#availability)。

## 模式生成与迁移

对于 MongoDB，我们不需要生成或迁移模式。

### 索引

适配器会创建与 SQL 数据库迁移所建索引对应的索引：

* 为每个标记为 `unique` 的字段创建唯一索引，例如 `user.email` 和 `session.token`。此索引可避免并发请求创建多个使用相同邮箱的用户。
* 为每个标记为 `index` 的字段创建索引。

创建 auth 实例并初始化适配器时，适配器会开始构建这些索引。请求不会等待构建完成；构建完成后才会强制执行唯一性。索引名称与 SQL 迁移保持一致，例如 `user_email_uidx` 和 `session_userId_idx`。

可选唯一字段会使用部分索引，因此许多文档可以不设置该字段或将其设为 `null`。插件声明的表级 `indexes` 会在向对应集合首次写入前创建。适配器会跳过：

* JSON 和数组字段。
* 已有单字段表级索引覆盖的字段。对于 `unique` 字段，该表级索引也必须是唯一索引。
* 设置了 `disableMigrations` 的表。

如果适配器无法创建字段索引，会记录错误并说明索引名称和原因。适配器会在没有该索引的情况下继续处理请求，也不会为了让索引构建成功而更改数据。常见原因如下：

* **集合中已有重复值。** 删除重复值之前，不会对该字段强制执行唯一性。在此期间，每次启动都会重新构建索引，并扫描整个集合。解决方法：

  1. 使用只读查询查找重复值。请使用日志消息中的集合和字段：

     ```ts
     const duplicates = await db
       .collection("user")
       .aggregate([
         { $match: { email: { $ne: null } } },
         { $group: { _id: "$email", ids: { $push: "$_id" }, count: { $sum: 1 } } },
         { $match: { count: { $gt: 1 } } },
       ])
       .toArray();
     ```

  2. 对每个重复值，决定保留哪个用户。重复记录可能来自不同的注册流程，因此请先检查 `emailVerified` 和关联账户。

  3. 对于要删除的用户，也请删除或迁移其 `session` 和 `account` 文档，这些文档的 `userId` 是被删除用户的 ID。MongoDB 不会自动删除它们。

  4. 重启应用以构建索引。
* **数据库用户没有创建索引的权限。** 授予其 `createIndex` 操作权限，或自行创建等效索引。适配器接受名称不同但等效的索引。
* **另一个索引使用相同的键或名称，但选项不同。** 删除该索引，然后重启应用。

发生网络错误或副本集选举后，适配器会在后续请求中重试。

## 联接

当 Better-Auth 需要通过单个查询从多个表中获取相关数据时，数据库联接非常有用。像 `/get-session`、`/get-full-organization` 以及许多其他端点都能从此功能中大幅受益，根据数据库延迟的不同，性能提升可达 2 倍至 3 倍。

MongoDB 适配器从版本 `1.4.0` 开始开箱即用地支持联接。要启用此功能，请在您的 auth 配置中将 `advanced.database.joins` 设置为 `true`。

```ts title="auth.ts"
import { betterAuth } from "better-auth";

export const auth = betterAuth({
  advanced: {
    database: {
      joins: true,
    },
  },
});
```
