仪表盘插件是您的 Better Auth 实例和 Better Auth 基础设施之间的核心连接。它为网页仪表盘提供实时数据，跟踪用户活动，并启用管理员 API。

## 仪表盘插件的功能

启用 `dash()` 后，Better Auth Infrastructure 仪表盘将为您提供：

* **用户管理** — 查看、搜索、封禁和删除用户
* **会话监控** — 查看活跃会话并撤销会话
* **组织概览** — 管理组织和成员
* **分析** — 跟踪注册、登录和活跃用户随时间的变化
* **审计日志** — 查询事件历史记录（[了解更多](/docs/infrastructure/plugins/audit-logs)）

## 安装

```ts
import { betterAuth } from "better-auth";
import { dash } from "@better-auth/infra";

export const auth = betterAuth({
  plugins: [
    dash(),
  ],
});
```

## 配置选项

### DashOptions

| 选项                   | 类型     | 描述                                                                                                                                                                                                                  |
| ---------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apiUrl`               | `string` | Better Auth Infrastructure API URL。默认值：`https://dash.better-auth.com`                                                                                                                                           |
| `kvUrl`                | `string` | KV 存储 URL。默认值：`https://kv.better-auth.com`                                                                                                                                                                     |
| `apiKey`               | `string` | 用于身份验证的 API 密钥。未设置时回退到环境变量 `BETTER_AUTH_API_KEY`。                                                                                                                                                  |
| `apiOptions`           | `object` | Dash API HTTP 客户端选项。接受 `timeout?: number`（毫秒，默认 `3000`）和 `headers?: Record<string, string>`。                                                                                                          |
| `kvOptions`            | `object` | KV HTTP 客户端选项。接受 `timeout?: number`（毫秒，默认 `1000`）、`retry?: { attempts?: number; baseDelay?: number; maxDelay?: number }`（默认值分别为 `2` / `400` / `600`）以及 `headers?: Record<string, string>`。 |
| `apiTimeout`           | `number` | `apiOptions.timeout` 的弃用别名。                                                                                                                                                                                      |
| `kvTimeout`            | `number` | `kvOptions.timeout` 的弃用别名。                                                                                                                                                                                       |
| `activityTracking`     | `object` | 活动跟踪配置。                                                                                                                                                                                                         |
| `managedDirectorySync` | `object` | 托管目录同步控制平面选项。                                                                                                                                                                                              |

### 活动跟踪

跟踪用户在您的应用中的最后活跃时间。启用后，用户活动时会自动更新 `lastActiveAt` 字段。

```ts
dash({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  activityTracking: {
    enabled: true,
    updateInterval: 300000,  // 更新间隔，单位毫秒（默认：5 分钟）
  },
}),
```

#### 模式变更

启用活动跟踪时，插件会在您的用户模式中添加一个字段：

```ts
user: {
  fields: {
    lastActiveAt: {
      type: "date",
    },
  },
}
```

<Callout type="warning">
  启用活动跟踪需要为 `lastActiveAt` 用户字段执行数据库迁移。请先运行迁移步骤，再依赖活动数据。
</Callout>

```package-install
npx auth@latest migrate
```

如果你的应用单独管理 schema 生成，请运行 `npx auth@latest generate`，并使用首选工具应用生成的迁移。

## 托管目录同步

托管目录同步是控制面板侧对 [SCIM 插件托管连接](/docs/plugins/scim/reference#managed-connection-catalog)的配套功能。当每个组织（租户）都应从控制面板获得目录连接，而无需在应用配置中为每个租户硬编码时，可使用此功能。

在 Better Auth 1.7 中，SCIM 支持三种连接模式：

* 在代码中静态定义连接
* 由应用管理的运行时验证
* 通过 `managedConnections` 管理的插件运行时连接

托管目录同步专为第三种模式设计，各层职责如下：

| 层                                | 职责                                                                                |
| -------------------------------- | ----------------------------------------------------------------------------------- |
| `scim({ managedConnections })`   | SCIM 协议、凭据目录、用户和群组预配                                                |
| `dash({ managedDirectorySync })` | 各组织连接的生命周期、控制面板 API，以及向应用投影数据                             |

启用控制平面后，还可添加可选功能：将用户投影到组织成员关系中、将目录与 SSO 配对以供登录，以及将 SCIM 属性映射到自定义字段。

### 启用托管目录同步

你需要启用 [organization](/docs/plugins/organization)、[SCIM](/docs/plugins/scim) 和 `dash` 插件。SCIM 必须使用 `managedConnections`，这样 Infrastructure 才能预留并签发每个租户的凭据。

```ts title="auth.ts"
import { betterAuth } from "better-auth";
import { organization } from "better-auth/plugins";
import { sso } from "@better-auth/sso";
import { scim } from "@better-auth/scim";
import { dash } from "@better-auth/infra";

export const auth = betterAuth({
  plugins: [
    organization(),
    sso({}),
    scim({
      connections: [],
      managedConnections: {
        credentialHashSecret: process.env.SCIM_CREDENTIAL_HASH_SECRET!,
      },
    }),
    dash({
      apiKey: process.env.BETTER_AUTH_API_KEY,
      managedDirectorySync: {
        enabled: true,
      },
    }),
  ],
});
```

<Callout type="warn">
  启用 `managedDirectorySync` 会添加预留表。请先运行迁移，再从控制面板创建目录。
</Callout>

```package-install
npx auth@latest migrate
```

如果你的应用单独管理 schema 生成，请运行 `npx auth@latest generate`，并使用首选工具应用生成的迁移。

完成设置后，可在 Infrastructure 控制面板中创建和管理目录（或使用[目录同步端点](#目录同步)）。

### 成员关系投影

目录连接后通常会启用成员关系投影：SCIM 预配或停用用户时，dash 会将该用户同步到拥有此目录的组织中。

启用托管目录同步时，此功能默认**开启**。

```ts
dash({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  managedDirectorySync: {
    enabled: true,
    membershipProjection: {
      enabled: true,
      role: "member", // role only when projection creates the membership
    },
  },
})
```

| 选项                           | 类型      | 描述                                                                          |
| ------------------------------ | --------- | ----------------------------------------------------------------------------- |
| `membershipProjection.enabled` | `boolean` | 安装用于组织成员关系的 SCIM `projection.reconcileUser`。默认值：`true`。       |
| `membershipProjection.role`    | `string`  | 投影**创建**成员关系时分配的角色。默认值：`"member"`。                       |

行为：

* 活跃目录用户会被加入组织（如果已经是成员，则关联到组织）。
* 停用用户的目录所拥有的成员关系会被移除。
* 系统会记录成员关系是由目录**创建**还是仅被**发现**（已存在）。投影只会更改其拥有的成员关系。

仅当 SCIM 应预配用户但不应更改组织成员关系时，才关闭此功能：

```ts
membershipProjection: {
  enabled: false,
}
```

### SSO 配对

SSO 配对会将托管目录与 SSO 提供者关联，使预配用户能够使用目录管理的同一身份登录。

此功能默认**开启**。仅当目录创建时要与 SSO **配对**，才需要使用此功能。

```ts
plugins: [
  sso({}),
  dash({
    apiKey: process.env.BETTER_AUTH_API_KEY,
    managedDirectorySync: {
      enabled: true,
      ssoPairing: true,
    },
  }),
]
```

| 选项         | 类型      | 描述                                    |
| ------------ | --------- | --------------------------------------- |
| `ssoPairing` | `boolean` | 安装 SSO 配对钩子。默认值：`true`。     |

说明：

* 配对登录会根据目录中配置的 SCIM 外部 ID 查找 Better Auth 用户。
* 如果只需要预配且从不创建配对目录，请设置 `ssoPairing: false`。

### 字段投影

字段投影会在目录同步时将 SCIM User 属性映射到 Better Auth 字段。在 Infrastructure 控制面板中按**每个目录连接**配置映射（或使用字段映射端点）。

此功能需**主动启用**，并会添加专用数据表。启用后请运行迁移，再配置映射。

```ts title="auth.ts"
import { betterAuth } from "better-auth";
import { organization } from "better-auth/plugins";
import { scim } from "@better-auth/scim";
import { dash } from "@better-auth/infra";

export const auth = betterAuth({
  user: {
    additionalFields: {
      employeeId: { type: "string", required: false },
      department: { type: "string", required: false },
    },
  },
  plugins: [
    organization({
      schema: {
        member: {
          additionalFields: {
            title: { type: "string", required: false },
            costCenter: { type: "string", required: false },
          },
        },
      },
    }),
    scim({
      connections: [],
      managedConnections: {
        credentialHashSecret: process.env.SCIM_CREDENTIAL_HASH_SECRET!,
      },
    }),
    dash({
      apiKey: process.env.BETTER_AUTH_API_KEY,
      managedDirectorySync: {
        enabled: true,
        fieldProjection: {
          enabled: true,
        },
      },
    }),
  ],
});
```

1. 声明要填充的 `user` / `member` 字段（如上所示）。
2. 运行迁移，创建字段映射表。
3. 在 Infrastructure 控制面板中打开目录连接，将 SCIM 路径映射到目标字段。

| 选项                      | 类型      | 描述                                                                             |
| ------------------------- | --------- | ---------------------------------------------------------------------------------- |
| `fieldProjection.enabled` | `boolean` | 添加字段映射 schema，并在 SCIM 同步时投影字段。默认值：`false`。                 |

#### 可投影字段

| 实体     | 可投影目标                                                            | 不可投影                                                                          |
| -------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `user`   | 可写的 `user.additionalFields`，以及加入允许列表的核心字段 `image`     | SCIM 管理的身份字段（`email`、`name`）；敏感键（`role`、`password`、封禁字段、双重认证密钥）；`input: false` 或引用字段 |
| `member` | 仅可写的 `organization.schema.member.additionalFields`                | 成员关系拥有的键（`role`、用户/组织 ID）。成员映射需要成员关系投影（默认开启） |

只有**由目录创建**的成员关系（`ownership: "created"`）会接收成员字段投影。已存在的成员关系不会更改。

#### SCIM 属性目录

映射从经过整理的 SCIM **User** 属性目录中读取：

| 路径                                                                                                  | 常见用途                                  |
| ----------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `userName`                                                                                            | 登录名 / 用户名                            |
| `primaryEmail` / `emails.primary`                                                                     | 邮箱类附加字段                              |
| `displayName`                                                                                         | 显示名称                                    |
| `externalId`                                                                                          | IdP 稳定 ID                                 |
| `name.formatted` / `name.givenName` / `name.familyName`                                               | 姓名组成部分                                |
| `title`                                                                                               | 职务                                        |
| `userType`                                                                                            | 用户分类                                    |
| `preferredLanguage` / `locale` / `timezone`                                                           | 地区设置                                    |
| `photos.primary`                                                                                      | 头像 URL → 通常映射到 `user.image`          |
| `enterprise.employeeNumber`                                                                           | 员工 ID                                     |
| `enterprise.costCenter` / `enterprise.organization` / `enterprise.division` / `enterprise.department` | 企业扩展属性                                |

系统会从持久化的 SCIM 用户记录中将值解析为字符串，然后转换为 Better Auth 字段类型（`string`、`number`、`boolean` 或 `date`）。

#### 投影模式

每个连接都会为每种实体（`user` 和 `member`）存储一种模式。默认模式为 **`create-only`**。

| 模式          | 行为                                                                                                                                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `create-only` | 首次预配时填充空目标（以及仍与静态 schema 默认值一致的值）。所有有效映射目标都设置后，该行的投影会冻结，以保留之后操作员所做的编辑。在冻结前，延迟到达的 SCIM 属性仍可写入。 |
| `reconcile`   | 只要目录拥有此个人资料/成员关系，就会在每次 SCIM 同步时重写映射字段。当 IdP 应继续作为这些字段的事实来源时，请使用此模式。 |

### 数据库 schema

当 `managedDirectorySync.enabled` 为 `true` 时，dash 插件会添加以下模型。Better Auth 会为每个模型提供主键字段 `id`。部分数据表仅在启用了选择性功能后才会安装。

#### `directorySyncConnection`

启用托管目录同步后始终存在。用于保存托管目录所属的组织、SCIM 连接、SSO 配对、生命周期和停用状态。

| 字段                     | 类型      | 约束                          | 描述                                           |
| ----------------------- | --------- | ----------------------------- | ---------------------------------------------- |
| `organizationId`        | `string`  | 必填，有索引                  | 拥有该目录的组织。                             |
| `providerId`            | `string`  | 必填                          | SSO 提供者标识符。                             |
| `aliasKey`              | `string`  | 必填，唯一，隐藏              | 内部目录别名。                                 |
| `provisioningDomainId`  | `string`  | 必填，唯一                    | SCIM 预配域。                                  |
| `activeOrganizationKey` | `string`  | 必填，唯一，隐藏              | 用于同步的活跃组织密钥。                       |
| `connectionId`          | `string`  | 可选，唯一                    | 托管 SCIM 连接标识符。                         |
| `creationRequestId`     | `string`  | 必填，唯一，隐藏              | 不可变的所有权关联值。                         |
| `status`                | `string`  | 必填                          | 当前目录生命周期状态。                         |
| `revision`              | `number`  | 必填，默认值 `0`，隐藏        | 用于并发控制的变更版本号。                     |
| `createdAt`             | `date`    | 必填                          | 创建时间戳。                                   |
| `createdByActorId`      | `string`  | 必填                          | 创建该目录的操作者。                           |
| `updatedAt`             | `date`    | 必填                          | 最后更新时间戳。                               |
| `lastActorId`           | `string`  | 必填                          | 最近一次变更的操作者。                         |
| `ssoProviderId`         | `string`  | 可选                          | 配对的 SSO 提供者 ID。                         |
| `ssoProviderRecordId`   | `string`  | 可选，有索引                  | 配对的 SSO 提供者记录。                        |
| `activeSsoProviderKey`  | `string`  | 必填，唯一，隐藏              | 活跃 SSO 提供者密钥。                          |
| `serializedSsoPairing`  | `string`  | 可选，隐藏                    | 序列化后的 SSO 配对元数据。                    |
| `pairingEnforced`       | `boolean` | 必填，默认值 `false`          | 是否强制执行 SSO 配对要求。                    |
| `unpairedAt`            | `date`    | 可选                          | 取消目录配对的时间。                           |
| `unpairedBy`            | `string`  | 可选                          | 移除配对的操作者。                             |
| `decommissionStartedAt` | `date`    | 可选                          | 开始停用的时间。                               |
| `decommissionedAt`      | `date`    | 可选                          | 完成停用的时间。                               |
| `lastError`             | `string`  | 可选，隐藏                    | 最近一次同步错误。                             |

| 字段                    | 类型     | 约束               | 描述                              |

| `userId`               | `string` | 必填，有索引       | 获得该成员关系的 Better Auth 用户。 |
| `memberId`             | `string` | 必填，唯一         | 组织 `member` 记录标识符。        |
| `ownership`            | `string` | 必填，隐藏         | `created` 或 `observed`。         |
| `provisioningDomainId` | `string` | 必填，有索引       | 创建该成员关系的 SCIM 预配域。    |
| `createdAt`            | `date`   | 必填               | 创建时间戳。                      |
| `updatedAt`            | `date`   | 必填               | 最后更新时间戳。                  |

| `entity`               | `string`  | 必填                   | 目标实体（`user` 或 `member`）。               |
| `targetField`          | `string`  | 必填                   | 该实体上的 Better Auth 字段名称。              |

| `enabled`              | `boolean` | 必填，默认值 `true`    | 是否在运行时应用此映射。                       |
| `createdAt`            | `date`    | 必填                   | 创建时间戳。                                   |

| `entity`               | `string` | 必填                          | 应用此模式的实体。         |
| `mode`                 | `string` | 必填，默认值 `create-only`    | 投影模式。                 |
| `createdAt`            | `date`   | 必填                          | 创建时间戳。               |
| `updatedAt`            | `date`   | 必填                          | 最后更新时间戳。           |
| `lastActorId`          | `string` | 必填                          | 最近一次变更的操作者。     |

#### `directorySyncFieldProvenance`

仅在 `fieldProjection.enabled` 为 `true` 时存在。标记某个预配域、实体和目标行是否已应用仅创建一次的字段。

| 字段                    | 类型     | 约束                   | 描述                                               |
| ---------------------- | -------- | ---------------------- | -------------------------------------------------- |
| `provenanceKey`        | `string` | 必填，唯一，隐藏       | 来源记录的稳定密钥。                               |
| `provisioningDomainId` | `string` | 必填，有索引           | SCIM 预配域。                                      |
| `entity`               | `string` | 必填                   | 被投影的实体。                                     |
| `targetId`             | `string` | 必填，有索引           | 被投影记录的主键（`userId`、`memberId` 等）。      |
| `appliedAt`            | `date`   | 必填                   | 冻结仅创建一次的字段的时间。                       |
| `createdAt`            | `date`   | 必填                   | 创建时间戳。                                       |
| `updatedAt`            | `date`   | 必填                   | 最后更新时间戳。                                   |

完整 SCIM 模型和迁移指南请参阅 [SCIM 插件参考](/docs/plugins/scim/reference)以及 [1.7 升级指南](/docs/guides/1-7-upgrade-guide)。

## 客户端集成

### dashClient()

客户端插件提供访问审计日志查询的功能：

```ts
import { createAuthClient } from "better-auth/client";
import { dashClient } from "@better-auth/infra/client";

export const authClient = createAuthClient({
  plugins: [dashClient()],
});
```

**注意**：对于 **Expo** 或 **React Native**，请从 `@better-auth/infra/native` 导入 `dashClient`（API 相同），并将其与 `sentinelNativeClient` 配合使用，具体请参阅 [Sentinel — Expo 和 React Native](/docs/infrastructure/plugins/sentinel#expo-和-react-native)。

### 配置

```ts
dashClient({
  resolveUserId: ({ userId, user, session }) => {
    return userId || user?.id || session?.user?.id;
  },
}),
```

### 获取当前用户的审计日志

返回**当前用户**的审计事件；如果您以成员身份传入 `organizationId`，则返回组织范围内的事件。

#### 基本查询

```ts
const session = await authClient.getSession();

const logs = await authClient.dash.getAuditLogs({
  session: session.data,
  limit: 50,
  offset: 0,
});

// Access the data
console.log(logs.data?.events);  // Array of audit log events
console.log(logs.data?.total);   // Total count
console.log(logs.data?.limit);   // Page size
console.log(logs.data?.offset);  // Current offset
```

更多信息请参阅[获取当前用户的审计日志](/docs/infrastructure/plugins/audit-logs#获取当前用户的审计日志)。

### 获取所有审计日志

返回当前用户拥有**管理员**或**所有者**访问权限的组织中的所有审计事件。角色检查需要[组织插件](/docs/plugins/organization)。

#### 基本查询

```ts
const session = await authClient.getSession();

const activity = await authClient.dash.getAllAuditLogs({
  session: session.data,
  limit: 50,
  offset: 0,
});

console.log(activity.data?.events);
console.log(activity.data?.total);
```

更多信息请参阅[获取所有审计日志](/docs/infrastructure/plugins/audit-logs#获取全部审计日志)。

## 最佳实践

1. **始终设置 API 密钥** — 没有它，插件无法与基础设施 API 通信。

2. **合理使用活动跟踪** — 更新间隔会影响数据库写入频率。对于高流量应用，考虑使用更长的间隔。

3. **监控审计日志保留期限** — 不同套餐的保留周期不同，请检查您的套餐限制。

4. **保护您的端点** — 仪表盘端点需要认证。确保您的仪表盘用户拥有适当权限。
