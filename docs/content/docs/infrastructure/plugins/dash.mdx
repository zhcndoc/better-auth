## 安装

```ts
import { betterAuth } from "better-auth";
import { dash } from "@better-auth/infra";

export const auth = betterAuth({
  plugins: [
    dash({
      apiUrl: process.env.BETTER_AUTH_API_URL,
      kvUrl: process.env.BETTER_AUTH_KV_URL,
      apiKey: process.env.BETTER_AUTH_API_KEY,
    }),
  ],
});
```

## 配置选项

### DashOptions

| 选项                     | 类型       | 描述                                                                                    |
| ---------------------- | -------- | ------------------------------------------------------------------------------------- |
| `apiUrl`               | `string` | Better Auth 基础设施 URL。默认值：[https://dash.better-auth.com](https://dash.better-auth.com) |
| `kvUrl`                | `string` | Better Auth 标识基础设施 URL。默认值：[https://kv.better-auth.com](https://kv.better-auth.com)   |
| `apiKey`               | `string` | 用于身份验证的 API 密钥。                                                                       |
| `apiOptions`           | `object` | Dash API HTTP 客户端选项。接受以毫秒为单位的 `timeout?: number`。                                     |
| `kvOptions`            | `object` | KV HTTP 客户端选项。接受 `timeout?: number` 和 `retry?: { attempts?: number; ... }`。           |
| `apiTimeout`           | `number` | `apiOptions.timeout` 的弃用别名。                                                           |
| `kvTimeout`            | `number` | `kvOptions.timeout` 的弃用别名。                                                            |
| `activityTracking`     | `object` | 活动跟踪配置。                                                                               |
| `managedDirectorySync` | `object` | Managed SCIM／directory-sync 控制平面选项。                                                   |

### 活动跟踪

```ts
dash({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  activityTracking: {
    enabled: true,           // 启用活动跟踪
    updateInterval: 300000,  // 更新间隔（毫秒），默认：5 分钟
  },
}),
```

启用后，会在用户 schema 中自动添加并更新 `lastActiveAt` 字段，记录用户最后活动时间。

### Managed Directory Sync

```ts
dash({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  managedDirectorySync: {
    enabled: true,
    ssoPairing: true,
    membershipProjection: {
      enabled: true,
      role: "member",
    },
  },
})
```

此可选控制平面用于 SCIM 1.7 插件管理的运行时流程。在 Better Auth 1.7 中，SCIM 支持三种连接模式：

* 静态代码定义的连接
* 应用拥有的运行时验证
* 通过 `managedConnections` 由插件管理的运行时连接

`managedDirectorySync` 选项启用 `dash` 中由插件管理的目录同步配置模式。它会创建管理目录连接和配对 SSO 状态所需的保留 schema 和 API。

#### Managed directory sync 选项

| 选项                             | 类型        | 描述                                                                       |
| ------------------------------ | --------- | ------------------------------------------------------------------------ |
| `enabled`                      | `boolean` | 启用由管理的 directory-sync 控制平面以及 SCIM 保留表／API。默认值：`false`。                   |
| `ssoPairing`                   | `boolean` | 安装 SSO `resolveUser` 和提供商变更钩子，当配对目录需要通过 SSO 协调用户身份时，这些钩子是必需的。默认值：`true`。 |
| `membershipProjection`         | `object`  | 当目录应创建群组或成员归属记录时，启用 SCIM 到组织成员归属的投影。                                     |
| `membershipProjection.enabled` | `boolean` | 启用投影钩子。默认值：`true`。                                                       |
| `membershipProjection.role`    | `string`  | 分配给投影组织成员归属的角色。默认值：`"member"`。                                           |

当应用希望 Better Auth 管理 SCIM 的运行时租户连接生命周期，并将其与基于 SSO 的身份解析配对时，请使用此选项。它适用于新的 1.7 流程，并与 `scim({ managedConnections })` 互补。

<Callout type="warning">
  启用 `managedDirectorySync` 需要对应的 Managed directory-sync 表数据库迁移。在使用管理运行时流程之前，请先运行迁移步骤。
</Callout>

```package-install
npx auth migrate
```

如果你的应用单独管理 schema 生成，请运行 `npx auth generate`，然后使用你偏好的工具应用生成的迁移。

### 数据库架构

当 `managedDirectorySync.enabled` 为 `true` 时，dash 插件会添加以下模型。Better Auth 会为每个模型提供主 `id` 字段。

#### `directorySyncConnection`

存储 Managed directory 的组织、SCIM 连接、SSO 配对、生命周期和停用状态。

| 列                       | 类型        | 约束              | 描述                  |
| ----------------------- | --------- | --------------- | ------------------- |
| `organizationId`        | `string`  | 必填，已建立索引        | 拥有该目录的组织。           |
| `providerId`            | `string`  | 必填              | SSO 提供商标识符。         |
| `aliasKey`              | `string`  | 必填，唯一，隐藏        | 内部目录别名。             |
| `provisioningDomainId`  | `string`  | 必填，唯一           | SCIM 配置域。           |
| `activeOrganizationKey` | `string`  | 必填，唯一，隐藏        | 用于协调的活动组织密钥。        |
| `connectionId`          | `string`  | 可选，唯一           | Managed SCIM 连接标识符。 |
| `creationRequestId`     | `string`  | 必填，唯一，隐藏        | 不可变的所有权关联值。         |
| `status`                | `string`  | 必填              | 当前目录生命周期状态。         |
| `revision`              | `number`  | 必填，默认值为 `0`，隐藏  | 用于并发控制的变更版本。        |
| `createdAt`             | `date`    | 必填              | 创建时间戳。              |
| `createdByActorId`      | `string`  | 必填              | 创建目录的操作者。           |
| `updatedAt`             | `date`    | 必填              | 上次更新时间戳。            |
| `lastActorId`           | `string`  | 必填              | 负责最新变更的操作者。         |
| `ssoProviderId`         | `string`  | 可选              | 配对的 SSO 提供商 ID。     |
| `ssoProviderRecordId`   | `string`  | 可选，已建立索引        | 配对的 SSO 提供商记录。      |
| `activeSsoProviderKey`  | `string`  | 必填，唯一，隐藏        | 活动 SSO 提供商密钥。       |
| `serializedSsoPairing`  | `string`  | 可选，隐藏           | 序列化的 SSO 配对元数据。     |
| `pairingEnforced`       | `boolean` | 必填，默认值为 `false` | 是否强制执行 SSO 配对要求。    |
| `unpairedAt`            | `date`    | 可选              | 目录解除配对的时间。          |
| `unpairedBy`            | `string`  | 可选              | 移除配对的操作者。           |
| `decommissionStartedAt` | `date`    | 可选              | 开始停用的时间。            |
| `decommissionedAt`      | `date`    | 可选              | 完成停用的时间。            |
| `lastError`             | `string`  | 可选，隐藏           | 最近一次协调错误。           |

#### `directorySyncMembershipProvenance`

跟踪通过目录同步投影创建或管理的组织成员归属，以便插件只协调其拥有的成员归属。

| 列                      | 类型       | 约束       | 描述                         |
| ---------------------- | -------- | -------- | -------------------------- |
| `membershipKey`        | `string` | 必填，唯一，隐藏 | 投影成员归属的稳定密钥。               |
| `organizationId`       | `string` | 必填，已建立索引 | 包含该成员归属的组织。                |
| `userId`               | `string` | 必填，已建立索引 | 接收该成员归属的 Better Auth User。 |
| `memberId`             | `string` | 必填，唯一    | 组织 `member` 记录标识符。         |
| `ownership`            | `string` | 必填，隐藏    | 投影所有权状态。                   |
| `provisioningDomainId` | `string` | 必填，已建立索引 | 生成该记录的 SCIM 配置域。           |
| `createdAt`            | `date`   | 必填       | 创建时间戳。                     |
| `updatedAt`            | `date`   | 必填       | 上次更新时间戳。                   |

有关完整的 SCIM 模型和迁移指南，请参阅 [SCIM 插件参考](/docs/plugins/scim/reference) 和 [1.7 升级指南](/docs/guides/1-7-upgrade-guide)。

## 客户端集成

### dashClient()

客户端插件支持审计日志查询功能：

```ts
import { createAuthClient } from "better-auth/client";
import { dashClient } from "@better-auth/infra/client";

export const authClient = createAuthClient({
  plugins: [dashClient()],
});
```

**注意**：对于 **Expo** 或 **React Native**，请从 `@better-auth/infra/native` 导入 `dashClient`（API 相同），并按照 [Sentinel — Expo and React Native](/docs/infrastructure/plugins/sentinel#expo-and-react-native) 中的描述与 `sentinelNativeClient` 配对使用。

### 配置

```ts
dashClient({
  resolveUserId: ({ userId, user, session }) => {
    // 自定义用户 ID 解析逻辑
    return userId || user?.id || session?.user?.id;
  },
}),
```

### 获取当前用户的审计日志

返回 **当前用户** 的审计事件；如果你以成员身份传入 `organizationId`，则返回组织范围内的事件。

#### 基本查询

```ts
const session = await authClient.getSession();

const logs = await authClient.dash.getAuditLogs({
  session: session.data,
  limit: 50,
  offset: 0,
});

// 访问数据
console.log(logs.data?.events);  // 审计日志事件数组
console.log(logs.data?.total);   // 总数
console.log(logs.data?.limit);   // 页面大小
console.log(logs.data?.offset);  // 当前偏移量
```

查看 [获取当前用户的审计日志](/docs/infrastructure/plugins/audit-logs#get-current-users-audit-logs) 以了解更多信息。

### 获取所有审计日志

返回当前用户具有 **admin** 或 **owner** 访问权限的组织的所有审计事件。需要 [organization 插件](/docs/plugins/organization) 进行角色检查。

#### 基本查询

```ts
const session = await authClient.getSession();

const activity = await authClient.dash.getAllAuditLogs({
  session: session.data,
  limit: 50,
  offset: 0,
});

console.log(activity.data?.events);
console.log(activity.data?.total);
```

查看 [获取所有审计日志](/docs/infrastructure/plugins/audit-logs#get-all-audit-logs) 以了解更多信息。

## Schema 扩展

启用活动跟踪后，插件会在用户 schema 中添加字段：

```ts
user: {
  fields: {
    lastActiveAt: {
      type: "date",
    },
  },
}
```

启用活动跟踪后，请确保执行数据库迁移。

## 最佳实践

1. **务必设置 API 密钥** —— 没有它，插件无法与基础设施 API 通信。

2. **合理使用活动跟踪** —— 更新间隔影响数据库写入。在高流量应用中，建议使用较长间隔。

3. **关注审计日志保留时间** —— 不同套餐有不同的保留期限，请确认你的套餐。

4. **保护你的端点安全** —— 仪表盘端点需身份验证，确保仪表盘用户拥有相应权限。
