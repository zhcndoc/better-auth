## 安装

```tsx
import { betterAuth } from "better-auth";
import { sentinel } from "@better-auth/infra";

export const auth = betterAuth({
  plugins: [
    sentinel({
      security: {
        // 在此配置安全功能
      },
    }),
  ],
});
```

## 配置选项

### SentinelOptions

| 选项              | 类型                   | 描述                                                                                                                                                                              |
| ----------------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apiUrl`          | `string`               | Better Auth infrastructure API URL. Default: `https://dash.better-auth.com`                                                                                                       |
| `kvUrl`           | `string`               | Better Auth identification infrastructure URL. Default: `https://kv.better-auth.com`                                                                                              |
| `apiKey`          | `string`               | Your API key for authentication. Falls back to `BETTER_AUTH_API_KEY` in env.                                                                                                      |
| `apiOptions`      | `object`               | Dash API HTTP options. Accepts `timeout?: number` (ms, default `3000`) and `headers?: Record<string, string>`.                                                                    |
| `kvOptions`       | `object`               | KV HTTP options. Accepts `timeout?: number` (ms, default `1000`), `retry?: { attempts?: number; baseDelay?: number; maxDelay?: number }`, and `headers?: Record<string, string>`. |
| `apiTimeout`      | `number`               | Deprecated alias for `apiOptions.timeout`.                                                                                                                                        |
| `kvTimeout`       | `number`               | Deprecated alias for `kvOptions.timeout`.                                                                                                                                         |
| `sentinelHeaders` | `"legacy" \| "modern"` | 身份识别和 PoW 使用的请求头名称。默认值：`"legacy"`。必须与客户端一致。请参阅[协议请求头](#protocol-headers-sentinelheaders)。                                                |
| `security`        | `SecurityOptions`      | Security feature configuration.                                                                                                                                                   |

### SecurityOptions

```ts
interface SecurityOptions {
  unknownDeviceNotification?: boolean;
  credentialStuffing?: CredentialStuffingConfig;
  impossibleTravel?: ImpossibleTravelConfig;
  geoBlocking?: GeoBlockingConfig;
  botBlocking?: boolean | { action: SecurityAction };
  suspiciousIpBlocking?: boolean | { action: SecurityAction };
  velocity?: VelocityConfig;
  freeTrialAbuse?: FreeTrialAbuseConfig;
  compromisedPassword?: CompromisedPasswordConfig;
  emailValidation?: EmailValidationConfig;
  emailNormalization?: { enabled?: boolean };
  staleUsers?: StaleUsersConfig;
  challengeDifficulty?: number;
}

type SecurityAction = "log" | "challenge" | "block";
```

## 安全功能

### 凭证填充防护

通过跟踪每个访客的登录失败次数，检测并阻止凭证填充攻击。

```ts
sentinel({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  security: {
    credentialStuffing: {
      enabled: true,
      action: "challenge", // optional default action; thresholds still drive challenge vs block
      thresholds: {
        challenge: 3,  // 失败 3 次后发起 PoW 挑战
        block: 5,      // 失败 5 次后封禁
      },
      windowSeconds: 3600,     // 1 小时时间窗口
      cooldownSeconds: 900,    // 封禁后 15 分钟冷却期
    },
  },
}),
```

**工作原理：**

1. 跟踪每个访客 ID 的登录失败尝试次数
2. 达到挑战阈值后，发出工作量证明（PoW）挑战
3. 达到封禁阈值后，完全封禁访客
4. 登录成功后自动清除失败尝试记录

### 不可能的旅行检测

检测用户在极短时间内从地理上相距遥远的地方登录。

```ts
sentinel({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  security: {
    impossibleTravel: {
      enabled: true,
      maxSpeedKmh: 1000,    // 最大合理旅行速度
      action: "challenge",  // 可选："log"、"challenge"或"block"
    },
  },
}),
```

**示例：** 如果用户先后在纽约和 30 分钟后在东京登录，这被视为不可能的旅行（即需要超过 1000 公里/小时的速度）。

### 免费试用滥用防护

通过设备指纹防止用户创建多个账户以滥用免费试用。

```ts
sentinel({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  security: {
    freeTrialAbuse: {
      enabled: true,
      thresholds: {
        challenge: 2,
        block: 3,
      },
      maxAccountsPerVisitor: 3,
      retentionSeconds: 90 * 24 * 60 * 60, // optional; default 90 days
      action: "block",
    },
  },
}),
```

**工作原理：**

1. 跟踪每个访客指纹的账户创建次数
2. 当超过阈值时，阻止新账户创建
3. 用于防止免费层滥用

`retentionSeconds` 控制每位访客的注册记录键保留时长（滑动窗口）。默认值为 90 天；平台会将值限制在 1 天到 365 天之间。

### 已泄露密码检测

通过查询 HaveIBeenPwned 数据库检查密码，检测泄露凭证。

```ts
sentinel({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  security: {
    compromisedPassword: {
      enabled: true,
      action: "block",      // 可选："log"、"challenge"或"block"
      minBreachCount: 1,    // 触发的最小泄露次数
    },
  },
}),
```

**隐私说明：** 采用 k-匿名技术 — 仅将密码哈希的前 5 个字符发送到 API，完整密码绝不发送。

### 过期账户监控

检测沉睡账户突然活跃，可能表示账户被接管。

```ts
sentinel({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  security: {
    staleUsers: {
      enabled: true,
      staleDays: 90,           // 账户超过 90 天视为沉睡
      action: "log",           // 可选："log"、"challenge"或"block"
      notifyUser: true,        // 向用户发送邮件通知
      notifyAdmin: true,       // 向管理员发送邮件通知
      adminEmail: "admin@yourapp.com",
    },
  },
}),
```

**通知包括：**

* 登录时间和位置
* 距离上次活跃的天数
* 设备信息

### 地理封禁

封禁或挑战特定国家的用户。

```ts
sentinel({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  security: {
    geoBlocking: {
      allowList: ["US", "CA", "GB"],  // 仅允许这些国家
      // 或者
      denyList: ["XX", "YY"],          // 封禁这些国家
      action: "block",                  // 可选："challenge"或"block"
    },
  },
}),
```

使用 ISO 3166-1 alpha-2 国家代码。

### 机器人封禁

检测并阻止自动化机器流量。

```ts
sentinel({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  security: {
    botBlocking: true,
    // 或使用自定义操作
    botBlocking: {
      action: "challenge",  // 可选："log"、"challenge"或"block"
    },
  },
}),
```

### 可疑 IP 检测

封禁来自已知恶意 IP 地址的请求。

```ts
sentinel({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  security: {
    suspiciousIpBlocking: true,
    // 或使用自定义操作
    suspiciousIpBlocking: {
      action: "block",
    },
  },
}),
```

### 访问速率限制 / 频率控制

限制各种操作的请求速率。

```ts
sentinel({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  security: {
    velocity: {
      enabled: true,
      thresholds: {
        challenge: 10,
        block: 20,
      },
      maxSignupsPerVisitor: 5,
      maxPasswordResetsPerIp: 10,
      maxSignInsPerIp: 50,
      windowSeconds: 3600,
      action: "challenge",
    },
  },
}),
```

### 邮箱验证

封禁一次性邮箱地址并验证邮箱域名。

```ts
sentinel({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  security: {
    emailValidation: {
      enabled: true,
      strictness: "medium",  // 可选："low"、"medium"、"high"
      action: "block",
      domainAllowlist: ["company.com", "partner.org"], // always allow these domains
    },
  },
}),
```

**严格级别：**

* `low` - 仅阻止已知一次性域名
* `medium` - 还检查有效的 MX 记录
* `high` - 额外的启发式检查

`domainAllowlist` 会跳过所列域名的一次性邮箱和启发式检查（必须精确匹配域名）。

### 邮箱规范化

Sentinel 会在注册和登录之前规范化邮箱地址，以防止别名和提供商的怪癖导致重复账户或登录不匹配。规范化包括将邮箱转为小写、在常见提供商上移除 plus-address 标签（例如 `user+tag@gmail.com` → `user@gmail.com`）、移除 Gmail 风格地址中的点，以及将 `googlemail.com` 映射到 `gmail.com`。

当你希望将此功能与一次性域名验证（`emailValidation`）分开控制时，请使用 `security.emailNormalization`：

```ts
sentinel({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  security: {
    emailValidation: {
      enabled: false, // 跳过一次性 / MX 检查
    },
    emailNormalization: {
      enabled: true, // 仍进行规范化以去重和保持一致的登录
    },
  },
}),
```

## Protocol headers (`sentinelHeaders`)

Sentinel 通过 HTTP 请求头传递访客身份和 PoW 挑战。默认的 `"legacy"` 名称（`X-Request-Id`、`X-Visitor-Id`、`X-PoW-*`）有时会被代理重写。将 `sentinelHeaders` 设为 `"modern"`，即可改用不易被代理改写的 `X-Sentinel-*` 名称。

此选项可用于 `sentinel()`、`sentinelClient()` 和 `sentinelNativeClient()`。默认值：`"legacy"`。服务器和客户端必须使用相同值。写入时只使用已配置的一组名称；读取时两组名称均可识别。

| 用途          | `"legacy"`（默认）  | `"modern"`                |
| ------------- | -------------------- | -------------------------- |
| 请求 ID       | `X-Request-Id`       | `X-Sentinel-Request-Id`    |
| 访客 ID       | `X-Visitor-Id`       | `X-Sentinel-Visitor-Id`    |
| PoW 挑战      | `X-PoW-Challenge`    | `X-Sentinel-PoW-Challenge` |
| PoW 原因      | `X-PoW-Reason`       | `X-Sentinel-PoW-Reason`    |
| PoW 解答      | `X-PoW-Solution`     | `X-Sentinel-PoW-Solution`  |

```ts title="auth.ts"
sentinel({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  sentinelHeaders: "modern",
})
```

```ts title="auth-client.ts"
sentinelClient({
  sentinelHeaders: "modern",
  autoSolveChallenge: true,
})
```

```ts title="auth-client.native.ts"
sentinelNativeClient({
  sentinelHeaders: "modern",
  autoSolveChallenge: true,
})
```

### 跨域 CORS

同源浏览器应用和原生客户端无需为 Sentinel 请求头配置 CORS。

跨域浏览器客户端则需要配置。访客 ID 和 PoW 请求头不属于简单请求头，因此认证 API 必须列出这些请求头的**确切名称**，浏览器才会发送或读取它们。对于带凭据的请求，不能使用 `Access-Control-Allow-Headers: *` 或 `Access-Control-Expose-Headers: *`。

请根据使用的请求头组（`sentinelHeaders`）配置 CORS：

|            | 预检时允许（请求头）                                                       | 响应中公开的请求头                                  |
| ---------- | --------------------------------------------------------------------------- | --------------------------------------------------- |
| `"legacy"` | `X-Request-Id`, `X-Visitor-Id`, `X-PoW-Solution`                            | `X-PoW-Challenge`, `X-PoW-Reason`                   |
| `"modern"` | `X-Sentinel-Request-Id`, `X-Sentinel-Visitor-Id`, `X-Sentinel-PoW-Solution` | `X-Sentinel-PoW-Challenge`, `X-Sentinel-PoW-Reason` |

* **允许（请求）**：客户端发送的请求头，包括请求 ID、访客 ID，以及重试挑战时发送的 PoW 解答。
* **公开（响应）**：客户端自动完成挑战时必须读取的请求头，包括 `423` 响应中的 PoW 挑战和原因。

如果服务器和客户端暂时使用不同的 `sentinelHeaders` 值，请同时允许和公开**两组**请求头，以确保双方仍能收发请求头。

`"modern"` 配置示例：

```ts
{
  // Your real app origin only — not "*"
  origin: "https://app.example.com",
  credentials: true,
  allowedHeaders: [
    "Content-Type",
    "Authorization",
    "X-Sentinel-Request-Id",
    "X-Sentinel-Visitor-Id",
    "X-Sentinel-PoW-Solution",
  ],
  exposedHeaders: [
    "X-Sentinel-PoW-Challenge",
    "X-Sentinel-PoW-Reason",
  ],
}
```

若使用 `"legacy"`，请将示例中的 `X-Sentinel-*` 名称替换为表中的旧版名称。

<Callout type="warn">
  请将 CORS 限制在你控制的来源内（请参阅[受信任来源](/docs/reference/security#trusted-origins)）。请勿在带凭据的认证请求中将 `origin` 设为 `"*"`。
</Callout>

## Proof-of-Work Challenges

当安全检查导致“challenge”动作时，Sentinel 会发起工作量证明（PoW）挑战，客户端必须完成挑战。

### PoW 工作原理

1. 服务器发出加密挑战
2. 客户端必须找到满足难度要求的解答
3. 解答计算开销大，但验证快速
4. 有效阻止自动化攻击，允许合法用户通过

### 挑战难度

```ts
sentinel({
  apiKey: process.env.BETTER_AUTH_API_KEY,
  security: {
    challengeDifficulty: 18,  // 默认难度等级
  },
}),
```

难度越高 = 计算量越大 = 攻击者越慢。

## 客户端集成

### sentinelClient()

客户端插件负责设备指纹识别及自动完成 PoW 挑战。

```ts
import { createAuthClient } from "better-auth/client";
import { sentinelClient } from "@better-auth/infra/client";

export const authClient = createAuthClient({
  plugins: [
    sentinelClient({
      autoSolveChallenge: true,
    }),
  ],
});
```

### 配置项

| Option                | Type                            | Default                                                                    | Description                                                                                                        |
| --------------------- | ------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `identifyUrl`         | `string`                        | `BETTER_AUTH_KV_URL` or `https://kv.better-auth.com`                       | Base URL for the identify endpoint.                                                                                |
| `identifyOptions`     | `object`                        | `{ timeout: 1000, retry: { attempts: 2, baseDelay: 400, maxDelay: 600 } }` | Identify HTTP timeout and retry policy.                                                                            |
| `sentinelHeaders`     | `"legacy" \| "modern"`          | `"legacy"`                                                                 | 访客 ID 和 PoW 的请求头名称。必须与服务器一致。请参阅[协议请求头](#protocol-headers-sentinelheaders)。 |
| `autoSolveChallenge`  | `boolean`                       | `true`                                                                     | Automatically solve PoW challenges.                                                                                |
| `kvTimeout`           | `number`                        | `1000`                                                                     | Deprecated alias for `identifyOptions.timeout`.                                                                    |
| `onChallengeReceived` | `(reason: string) => void`      | —                                                                          | Called when a PoW challenge is received.                                                                           |
| `onChallengeSolved`   | `(solveTimeMs: number) => void` | —                                                                          | Called after a successful solve.                                                                                   |
| `onChallengeFailed`   | `(error: Error) => void`        | —                                                                          | Called if solving fails.                                                                                           |

### 浏览器指纹

客户端会通过访客 ID 请求头（`X-Visitor-Id`；当 `sentinelHeaders: "modern"` 时为 `X-Sentinel-Visitor-Id`）自动在请求中附带访客 ID。此指纹用于：

* 凭证填充检测
* 免费试用滥用防护
* 设备跟踪

### PoW 解答请求头

启用自动解答后，已解答的挑战会通过 PoW 解答请求头发送（`X-PoW-Solution`；当 `sentinelHeaders: "modern"` 时为 `X-Sentinel-PoW-Solution`）。

### Expo 和 React Native

对于 **Expo** 和 **React Native** 应用，使用 `@better-auth/infra/native` 中的 `sentinelNativeClient`，而不是使用 `@better-auth/infra/client`。

对于 **React Native** 应用，安装以下对等依赖：

```package-install
@react-native-async-storage/async-storage react-native-get-random-values
```

`@react-native-async-storage/async-storage` 是可选的。如果未安装，客户端使用仅会话的内存访客 ID。对于生产环境，请安装它或传递自定义 `storage`（例如安全存储）。

#### 示例

```ts

export const authClient = createAuthClient({
  baseURL: "https://your-api.example.com",
  plugins: [
    dashClient(),
    sentinelNativeClient({
      autoSolveChallenge: true,
    }),
  ],
});
```

对于 **Expo** 应用，安装以下软件包以获得更丰富的原生身份信息。

<Callout type="info">
  **Expo：** 在添加基础设施插件之前，请遵循 [Expo 集成](/docs/integrations/expo) 指南。
</Callout>

```package-install

```

```ts
import { createAuthClient } from "better-auth/react";
import { expoClient } from "@better-auth/expo/client";

  plugins: [
    expoClient({
      scheme: "myapp",

```

| `sentinelHeaders`     | `"legacy" \| "modern"`          | `"legacy"`                                                                 | 访客 ID 和 PoW 的请求头名称。必须与服务器一致。请参阅[协议请求头](#protocol-headers-sentinelheaders)。 |

| `onChallengeReceived` | `(reason: string) => void`      | —                                                                          | Called when a PoW challenge is received.                                                                           |

| `storage`             | `{ getItem, setItem }`          | Async Storage when installed                                               | Persistent async storage for a stable per-install visitor ID.                                                      |

## 安全事件

Sentinel 会将安全活动记录为审计事件：

| 事件类型          | 描述                                                                                                                                                       |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `security_check`  | 每个受保护的用户操作记录一个事件。`eventData.outcome` 为 `passed`、`challenged` 或 `blocked`。包含 `evaluatedChecks`、`triggeredBy` 和 `reason`。             |
| `security_signal` | 为安全仪表盘提供检测详情，不计入安全用量。                                                                                                                  |

这些事件会显示在 Security 控制面板中，并包含在[审计日志](/docs/infrastructure/plugins/audit-logs)中。

```ts
import { betterAuth } from "better-auth";
import { sentinel } from "@better-auth/infra";

export const auth = betterAuth({

    sentinel({

      security: {
        // 核心防护

          enabled: true,
          thresholds: { challenge: 3, block: 5 },
        },
        compromisedPassword: {
          enabled: true,

        },
        emailValidation: {
          enabled: true,
          strictness: "medium",
          action: "block",
        },
        
        // 基于位置的策略
        impossibleTravel: {
          enabled: true,
          action: "challenge",
        },
        geoBlocking: {
          denyList: ["XX"],
          action: "block",
        },
        
        // 滥用防护
        freeTrialAbuse: {
          enabled: true,
          maxAccountsPerVisitor: 3,
          action: "block",
        },
        velocity: {
          enabled: true,
          maxSignupsPerVisitor: 5,
          action: "challenge",
        },
        
        // 机器人防护
        botBlocking: { action: "challenge" },
        suspiciousIpBlocking: { action: "block" },
        
        // 账户监控
        staleUsers: {
          enabled: true,

          notifyAdmin: true,
          adminEmail: "security@yourapp.com",
        },
      },
    }),
  ],
});
```

## 最佳实践

1. **先从日志开始** - 初期将动作设置为“log”，以了解流量模式，再决定是否封禁。

2. **调整阈值** - 每个应用都不同，监控误报率并相应调整阈值。

3. **先使用挑战，后使用封禁** - 挑战能阻挡自动化攻击，同时允许合法用户访问。

4. **启用客户端自动解决** - 在浏览器中使用 `sentinelClient({ autoSolveChallenge: true })`，或在 Expo / React Native 中使用 `sentinelNativeClient({ autoSolveChallenge: true })`。

5. **监控安全事件** - 定期查看安全控制台，识别攻击趋势。

6. **设置管理员通知** - 对关键事件如沉睡账户激活启用 `notifyAdmin`。

## 疑难解答

### 缺少 API 密钥警告

```
[Sentinel] 缺少 BETTER_AUTH_API_KEY。安全检查可能回退到允许模式。
```

请确保正确设置了 API 密钥环境变量。

### 挑战无法执行

如果 PoW 挑战无法解决：

1. 验证正确的客户端插件：Web 使用 `sentinelClient()`（来自 `@better-auth/infra/client`），Expo / React Native 使用 `sentinelNativeClient()`（来自 `@better-auth/infra/native`）
2. 检查 `autoSolveChallenge` 是否为 `true`
3. 确保客户端可以访问服务器

### 误报率过高

如果合法用户被阻止：

1. 增加阈值
2. 将操作从“block”改为“challenge”
3. 查看安全事件以识别模式
