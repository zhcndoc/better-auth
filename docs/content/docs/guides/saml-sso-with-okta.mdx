本指南将以 Okta 为例，介绍如何通过身份提供者（IdP）设置 SAML 单点登录（SSO）。所有 SAML 选项请参阅 [SAML 提供者](/docs/plugins/sso/saml)和 [SSO 参考](/docs/plugins/sso/reference)。

## 什么是 SAML？

SAML（安全断言标记语言）是一种基于 XML 的标准，用于在身份提供商（IdP）（例如 Okta、Azure AD、OneLogin）与服务提供商（SP）（此处为 Better Auth）之间交换身份验证和授权数据。

在该配置中：

* **IdP (Okta)**：对用户进行身份验证并发送有关其身份的断言
* **SP (Better Auth)**：验证断言并登录用户

### 第一步：在 Okta 中创建 SAML 应用

1. 登录 Okta 管理控制台

2. 导航至 Applications > Applications

3. 点击“Create App Integration”

4. 选择“SAML 2.0”作为登录方式

5. 配置以下设置：

   * **Single Sign-on URL**：你的 Better Auth 回调端点（例如，`http://localhost:3000/api/auth/sso/saml2/sp/acs/sso`）。注意：`sso` 是你的 `providerId`
   * **Audience URI (SP Entity ID)**：你的 Better Auth 元数据 URL（例如，`http://localhost:3000/api/auth/sso/saml2/sp/metadata`）
   * **Name ID format**：Email Address 或你选择的任意格式

6. 下载 IdP 元数据 XML 文件和证书

<Callout type="warn">
  **由 IdP 发起的 SSO**：若要让用户从 IdP 控制面板发起登录，请将 **Single Sign-on URL** 指向 `/api/auth/sso/saml2/sp/acs/{providerId}`，并在 `sso()` 选项中设置 `saml: { allowIdpInitiated: true }`。此选项默认关闭，因为开启后，任何拥有 IdP 账户的人都可能让受害者登录攻击者的账户。该设置适用于所有 SAML 提供者。仅在 IdP 要求时启用；请参阅[由 IdP 发起的 SSO](/docs/plugins/sso/saml#idp-initiated-sso)。
</Callout>

### 第二步：配置 Better Auth

以下是在开发环境中为 Okta 配置的示例：

```typescript
const ssoConfig = {
  defaultSSO: [{
    domain: "localhost:3000", // 你的域名
    providerId: "sso",
    samlConfig: {
      // 服务提供商配置
      issuer: "http://localhost:3000/api/auth/sso/saml2/sp/metadata",
      entryPoint: "https://trial-1076874.okta.com/app/trial-1076874_samltest_1/exktofb0a62hqLAUL697/sso/saml",
      // IdP Configuration
      idpMetadata: {
        entityID: "https://trial-1076874.okta.com/app/exktofb0a62hqLAUL697/sso/saml/metadata",
        singleSignOnService: [{
          Binding: "urn:oasis:names:tc:SAML:2.0:bindings:HTTP-Redirect",
          Location: "https://trial-1076874.okta.com/app/trial-1076874_samltest_1/exktofb0a62hqLAUL697/sso/saml"
        }],
      },
      cert: `-----BEGIN CERTIFICATE-----
MIIDqjCCApKgAwIBAgIGAZhVGMeUMA0GCSqGSIb3DQEBCwUAMIGVMQswCQYDVQQGEwJVUzETMBEG
...
[你的 Okta 证书]
...
-----END CERTIFICATE-----`,
      // Better Auth generates the SP metadata from `issuer` and the ACS URL.
      // If you supply your own `spMetadata.metadata`, its entityID becomes the SP entity ID and the default audience.
    }
  }]
}
```

### 第三步：多个默认提供商（可选）

你可以为不同域配置多个 SAML 提供商：

```typescript
const ssoConfig = {
  defaultSSO: [
    {
      domain: "company.com",
      providerId: "company-okta",
      samlConfig: {
        // company.com 的 Okta SAML 配置
      }
    },
    {
      domain: "partner.com", 
      providerId: "partner-adfs",
      samlConfig: {
        // partner.com 的 ADFS SAML 配置
      }
    },
    {
      domain: "contractor.org",
      providerId: "contractor-azure",
      samlConfig: {
        // contractor.org 的 Azure AD SAML 配置
      }
    }
  ]
}
```

<Callout type="info">
  **显式指定**：登录时直接传入 providerId
  **域名回退**：根据用户的邮箱域名进行匹配。例如 [user@company.com](mailto:user@company.com) → 匹配 `company-okta` 提供商。
</Callout>

### 第四步：发起登录

**1. 通过 `providerId` 显式指定（推荐）：**

```typescript
// 显式指定使用哪个提供商
await authClient.signIn.sso({
  providerId: "company-okta",
  callbackURL: "/dashboard"
});
```

**2. 根据邮箱域名匹配：**

```typescript
// 根据邮箱域名自动匹配提供商
await authClient.signIn.sso({
  email: "user@company.com",
  callbackURL: "/dashboard"
});
```

**3. 指定域名进行匹配：**

```typescript
// 显式指定域名进行匹配
await authClient.signIn.sso({
  domain: "partner.com",
  callbackURL: "/dashboard"
});
```

**重要注意事项**：

* The example uses `localhost:3000` - adjust URLs for your environment
* For production, always use proper IdP providers like Okta, Azure AD, or OneLogin
* The ACS URL is derived automatically from `{baseURL}/sso/saml2/sp/acs/{providerId}`. The post-login destination is controlled by `callbackURL` in `signIn.sso()`

### 第五步：动态注册 SAML 提供商

若要动态注册，请使用 API 注册 SAML 提供者。详细步骤请参阅 [SSO 插件文档](/docs/plugins/sso/saml#register-a-saml-provider)。

注册示例：

```typescript
await authClient.sso.register({
  providerId: "okta-prod",
  issuer: "https://your-domain.com",
  domain: "your-domain.com",
  samlConfig: {
    // 你的生产环境 SAML 配置
  }
});
```
